# 口袋 Pocket · 架构设计

## 1. 要解决的问题

用 AI 快速产出的作品多为单个 HTML 文件或小型前端工程。直接塞进手机浏览器会遇到：

| 问题 | 原因 |
|---|---|
| 画面尺寸错乱 | 缺少正确的 viewport、`100vh` 被系统栏侵占 |
| 顶部被状态栏压住 | 没有安全区概念 |
| 输入框被键盘遮住 | 没有 IME inset 处理 |
| `fetch` 报跨域 | 浏览器同源策略 |
| localStorage 失效 | `file://` 下存储受限 |
| 深色模式错乱 | 没有统一主题策略 |
| 每个作品一个 APK | 安装包泛滥、签名混乱、被安全软件拦截 |

口袋的做法：**一个宿主 App + 可导入的插件包**。宿主提供真正的手机 App 外壳（首页、桌面、管理、设置），插件只是一段网页，但被放到一个受控的、真实的 https 环境里运行。

## 2. 总体结构

```
┌──────────────────────────────────────────────────────┐
│  Pocket 宿主 APK（io.pocket.host）                     │
│                                                      │
│  MainActivity（Compose）                              │
│   ├── 应用桌面：网格卡片 + 使用记录                      │
│   ├── 导入：文件选择 / 粘贴 HTML / 内置示例              │
│   ├── 管理：详情、清除数据、删除                         │
│   └── 设置：存储统计、关于                              │
│                                                      │
│  AppRunnerActivity（全屏容器）                         │
│   └── WebView                                         │
│        ├── 虚拟源 https://<id>.pocket.local           │
│        ├── PocketWebViewClient（拦截 + 注入 + 导航策略）  │
│        └── PocketBridge（@JavascriptInterface）        │
│                                                      │
│  内核                                                 │
│   ├── PackageInstaller  .pkt 解包 / 校验 / 原子替换      │
│   ├── PackageRepository 索引持久化 + 使用统计            │
│   ├── PocketStorage    按应用隔离的键值存储              │
│   └── SafeZip          路径逃逸 / 体积 / 数量防护         │
└──────────────────────────────────────────────────────┘
```

## 3. 为什么用虚拟 https 源

Android 官方明确不建议用 `file://` 加载本地 HTML（`WebView` unsafe file inclusion）。口袋改用一个虚拟域名：

```
https://<appId>.pocket.local/<path>
        ↓ WebViewClient.shouldInterceptRequest
files/apps/<appId>/www/<path>
```

带来的好处：

1. **真实安全上下文**：`localStorage`、`IndexedDB`、`fetch`、ES Module、相对路径、`crypto.subtle` 全部按 https 规则工作。
2. **天然多 origin 隔离**：域名带 `appId`，两个应用互相看不到对方的存储，不需要多进程。
3. **可控**：只有当前应用的 host 会被拦截并读取本地文件；其余 http(s) 请求走网络，非网络协议一律 403。
4. **无 CORS 干扰**：页面里的资源请求都在同一 origin 下。

### 拦截规则

```
scheme == https 且 host == 当前应用 host
    → 读 files/apps/<id>/www/<path>，按扩展名给 MIME，支持 Range
    → HTML 会被改写：插入 <meta viewport> 与 <script src="/__pocket/sdk.js">
scheme == http/https 且 host 不同
    → 返回 null，交给系统网络栈（CDN、图片、字体正常加载）
其他协议（file:// / content:// / intent:// / javascript://）
    → 403
```

顶层导航由 `shouldOverrideUrlLoading` 单独管控：只有本应用 host 允许在 WebView 内跳转，外部链接交给系统浏览器（需 `external` 权限）。

## 4. SDK 注入时机

SDK 必须在页面任何业务脚本之前执行，否则 `window.pocket` 可能尚未定义。做法不是 `evaluateJavascript`（时机不确定），而是在**返回 HTML 字节前**把引导脚本写进 `<head>` 之后：

```html
<head>
  <meta name="viewport" ...>
  <script src="/__pocket/sdk.js"></script>
  ...
```

`sdk.js` 是阻塞脚本，保证在后续脚本执行前完成初始化。SDK 内部用 `window.__isPocketSdk` 去重，多个页面重复注入也不会重复初始化。

## 5. Bridge 协议

`WebView.addJavascriptInterface(bridge, "PocketNative")`，只暴露两个方法：

```js
PocketNative.call(JSON)      // 同步，返回 JSON 字符串
PocketNative.callAsync(JSON) // 异步，通过 window.__pocketResolve(id, JSON) 回调
```

请求：

```json
{ "method": "ui.toast", "params": { "text": "你好" } }
{ "id": 7, "method": "http.request", "params": { "url": "..." } }
```

响应：

```json
{ "ok": true, "data": ... }
{ "ok": false, "code": "E_PERMISSION", "message": "..." }
```

同步方法（存储、设备信息、界面开关）直接返回结果；异步方法（对话框、文件选择、网络请求）通过 `id` 匹配 Promise。

选择 `@JavascriptInterface` 而不是较新的 `WebMessageListener`，是为了兼容国产 ROM 上较旧的 WebView。因为只加载自己签发的本地资源，且外部页面无法进入当前 WebView，注入面是可控的。

## 6. 权限与网络白名单

manifest 的 `permissions` 是**默认拒绝**的白名单。Bridge 每个能力入口先查 `requirePermission()`，未声明直接抛 `E_PERMISSION`，不会静默降级。

网络多一层：`http.request` 的域名必须在 `manifest.network.whitelist` 内，否则弹出一次确认框，用户允许后写入该应用的 `extraHosts`，下次不再询问。

## 7. 数据模型

```
files/
├── apps.json                     # 已安装应用索引（含统计）
├── apps/
│   └── <appId>/
│       ├── www/                  # 网页资源（升级时整体替换）
│       │   ├── manifest.json
│       │   ├── index.html
│       │   └── icon.png
│       └── data/storage.json     # pocket.storage 落盘
└── tmp/                          # 导入解包临时目录
```

`InstalledApp` 记录：

- 安装信息：`id / name / version / description / accent / entry / permissions / whitelist`
- 使用记录：`installedAt / lastUsedAt / launchCount / totalForegroundMs`
- 体积：`sizeBytes`

统计在 `AppRunnerActivity.onResume` 开始计时、`onPause` 累加，`onCreate` 记一次打开次数。

## 8. 数据隔离与清除

- **隔离**：每个应用独立 origin、独立目录，`pocket.storage` 独立 JSON 文件。
- **清除数据**：删除 `data/` 目录，并给该应用打上 `wipeRequested` 标记；下次打开时在页面加载完成后执行 `localStorage.clear()`、删除 IndexedDB、清空 Cache Storage，然后清除标记。这样不需要额外启动隐藏 WebView，也不会误伤其他应用。
- **删除应用**：删除整个 `apps/<id>/` 并从索引移除。

## 9. 生命周期

```
MainActivity
  └── 点击卡片 / 详情页「打开」
        ↓ Intent(EXTRA_APP_ID)
AppRunnerActivity
  ├── onCreate  读取 manifest，配置方向 / 状态栏 / WebView / 统计
  ├── onResume  开始前台计时，向 JS 派发 resume
  ├── onPause   累加时长，派发 pause
  ├── onBackPressed → 先问 JS __pocketDispatchBack()
  │                    true  → 插件消费（例如关闭自己的弹层）
  │                    false → 退出应用
  └── onDestroy 派发 destroy，销毁 WebView
```

## 10. 安全基线

| 项 | 策略 |
|---|---|
| 文件访问 | `allowFileAccess=false`、`allowContentAccess=false`、禁止 file URL 跨源 |
| 导航 | 白名单 host，其他协议一律拦截 |
| Bridge 暴露范围 | 只在本地 origin 的 WebView 中注入 |
| 包解压 | zip-slip 防护、64MB 总量、4000 文件上限、单文件 32MB |
| 外部链接 | 交系统浏览器，需 `external` 权限 |
| 签名 | 固定自签 keystore，保证升级覆盖安装 |

## 11. 可扩展方向

- iOS 版：同样架构换成 `WKWebView` + `WKURLSchemeHandler`
- 局域网推送 `.pkt`（开发时免传输）
- 插件间通信（当前刻意不做，保持数据隔离）
- 应用图标自定义上传、主题色自动取色
