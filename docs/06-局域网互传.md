# 局域网互传与剪贴板（1.4.0）

> 目标：同一 Wi-Fi 下，手机 ↔ 电脑（以后手机 ↔ 手机）高速互传任意文件；不经过 QQ/微信/网盘。
> 传输文件与系统文件分开存放，由内置「口袋文件」统一管理。

## 1. 角色与端口

| 角色 | HTTP 端口 | UDP 发现 |
| --- | --- | --- |
| 手机宿主（口袋 App） | 8572（被占用则 8573…8579） | 8571 收发 |
| 电脑端（`pocket serve`） | 8570 | 8571 收发 |

两端都同时是「服务端 + 客户端」：谁都可以向对方发文件。

## 2. 发现协议（UDP 8571）

探测包（明文）：

```
POCKET_DISCOVER/1
```

设备应答 / 每 5 秒广播（JSON，UTF-8）：

```json
{
  "service": "pocket",
  "id": "设备唯一 id",
  "name": "设备名",
  "platform": "android | windows",
  "host": "本机在局域网里的 IP（可省略，接收方以包的来源 IP 为准）",
  "port": 8572,
  "transferPort": 8572,
  "version": 1
}
```

- 收到探测包：立即回一份自己的 JSON。
- 收到 JSON 且 `service == "pocket"`：记入设备表，`lastSeen = now`，20 秒没更新就丢弃。
- 自己发的广播按 `id` 过滤，不出现在自己的设备列表里。
- 兼容旧的导入逻辑：`platform == "android"` 的设备不出现在「从电脑导入」列表里。

### 广播不通时的兜底（1.3.1）

实测 Windows 移动热点下，电脑 → 手机的广播收不到（手机 → 电脑能到），所以不能只依赖广播：

- 手机每 5 秒向 **默认网关**（热点场景下就是电脑）、**本网段广播地址**、**记住过的设备** 各发一份
  「自我介绍 JSON + `POCKET_DISCOVER/1` 探测包」。
- 电脑端每 5 秒向 `255.255.255.255`、各网卡定向广播地址（如 `192.168.137.255`）发自我介绍，
  并向记住过的设备单播探测包。
- 两端都会把发现过的设备写进本地（手机 SharedPreferences / 电脑 `library/.pocket-devices.json`），
  之后靠单播找回。

`GET /api/transfer/debug` 可查看电脑端当前的网卡、广播地址、记住的设备、UDP 包计数与最后一条 payload，排查发现问题时很有用。

## 3. HTTP 接口（手机 8572 / 电脑 8570 同构）

统一返回 JSON；文件接口支持 `Range`；所有响应带 CORS（桌面网页要直接 PUT 到手机）：

```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Range
```

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/transfer/info` | `{ok,id,name,platform,port,version}` |
| POST | `/api/transfer/offer` | 申请传输：`{from:{id,name,platform}, files:[{name,size,mime}]}` → `{ok,token,accepted}` |
| PUT | `/api/transfer/upload/<token>/<index>` | 裸字节流；带 `Content-Length` 或 `Transfer-Encoding: chunked` |
| GET | `/api/transfer/files` | `{ok, files:[{id,name,size,mime,time,direction,peer}]}` |
| GET | `/api/transfer/file/<id>` | 下载 / 预览，支持 Range |
| DELETE | `/api/transfer/file/<id>` | 删除 |
| POST | `/api/transfer/delete` | `{id}`，DELETE 的兼容写法 |

约定：

- `offer` 默认自动接受（自己的局域网），返回的 `token` 10 分钟有效，绑定文件列表与来源。
- `index` 是 `offer.files` 里的下标；文件名以 offer 为准，避免路径穿越。
- 单个文件不设硬上限，但按磁盘剩余空间做保护。
- 以后给「小应用与电脑高频交换数据」预留：接口都以 `/api/transfer/*` 分组，可加 `/api/data/*`，不影响现有实现。

## 4. 文件存放

手机（应用私有，不出现在系统相册/下载里）：

```
/data/data/io.pocket.host/files/transfer/
├── index.json                     传输记录（id/名称/大小/方向/来源/时间/相对路径）
├── inbox/2026-11-08/<时间戳>_名字  收到的
└── sent/2026-11-08/<时间戳>_名字   发出的（用于「我发过什么」）
```

电脑：

```
library/transfer/                  收到的文件（与 library/ 里的 HTML 收藏分开）
```

- 手机端「口袋文件」内置应用负责浏览、预览、重命名、删除、导出到系统下载目录。
- 预览走 `https://<appId>.pocket.local/__pocket/files/<id>`，由 `PocketWebViewClient` 直接返回本地文件，不经过 base64。

## 5. JS SDK

```js
pocket.transfer.status()                       // {running, port, ip, deviceId, deviceName}
pocket.transfer.devices()                      // [{id,name,platform,host,port,lastSeen}]
pocket.transfer.pickAndSend(deviceId)          // 原生选文件后直接流式发送，返回 {sent:[名称]}
pocket.transfer.sendStored(deviceId, [fileId]) // 把「口袋文件」里的文件发给设备

pocket.files.list({ direction: 'in' })         // [{id,name,size,mime,time,direction,peer}]
pocket.files.rename(id, name)
pocket.files.delete([id])
pocket.files.export(id)                        // 存到系统下载目录，返回 {ok,path}
pocket.files.url(id)                           // '/__pocket/files/<id>'，同源可直接 <img>/<video>

pocket.on('transfer.received', fn)             // {file:{...}}
pocket.on('transfer.progress', fn)             // {name,sent,total,percent}
```

## 6. 生命周期与限制

- 手机服务随 App 进程启动（`PocketApp.onCreate`）；App 被系统杀掉后服务停止，重新打开即恢复。
- 锁屏 / 息屏时 Wi-Fi 可能休眠，长传建议保持屏幕常亮（传输应用里会 `keepScreenOn`）。
- 目前是「局域网内可信设备」模型：不设账号，收到即存；后续可加确认弹窗与信任设备列表。

## 7. 剪贴板共享与电脑悬浮窗（1.4.0）

两端各存一份「多轮剪贴板历史」，通过同一套局域网 HTTP 接口互相拉取、按文字去重合并：

| 端 | 文件 | 上限 |
| --- | --- | --- |
| 手机 | `files/clipboard.json` | 50 条 |
| 电脑 | `library/clipboard.json` | 50 条 |

```
GET    /api/clipboard             → {ok, items:[{id,text,time,source:'phone'|'pc'}]}
POST   /api/clipboard             ← {text, source?, time?}，按 text 去重
DELETE /api/clipboard/<id>
POST   /api/clipboard/clear
```

- 手机「剪贴板」内置应用：打开时自动读取一次系统剪贴板并记录，支持列表复制、删除、清空、`同步电脑`。
- **实时剪贴板（1.5.0）**：在剪贴板应用里打开开关，授权「口袋剪贴板」无障碍服务后，`PocketClipboardService` 会在后台监听剪贴板变化和文字选中事件，写入手机 `clipboard.json`；电脑端每 1.5 秒轮询手机 `/api/clipboard`，因此手机复制后 1~2 秒会出现在电脑端。
  - Android 10+ 不允许普通后台应用直接 `getPrimaryClip()`；服务优先读剪贴板，读不到时用无障碍节点的选中文本兜底。
- 手机自动同步：`clipboard.sync` 通过 UDP 发现的 `platform != android` 设备，直接 GET 电脑端 `/api/clipboard`，合并进本地。
- 电脑端页面新增「剪贴板」区，可查看、复制、删除；`POST /api/float/start` 打开桌面应用。

电脑端应用（`desktop/`，Electron，打包为 `dist/desktop/Pocket-win32-x64/Pocket.exe`）：

- 默认 100px 深蓝玻璃悬浮球，只显示大 P（无流光、无文字）；点击打开 1180×760 工作台，右上角可收起回球。
- 左侧玻璃边栏 + 顶部问候/搜索；概览含 4 张指标卡、7/14 天剪贴板活动图、深色「当前连接」卡、最近剪贴板/文件列表；另有文件 / 剪贴板 / 设备 / 资源库 / 设置页。
- **资源库**：左侧「资源库」（或 Ctrl+Shift+L）原生管理小应用（.pkt）、HTML 收藏和手机安装包，不再打开旧网页管理页。
- **悬浮窗**（Ctrl+Shift+B / 托盘 / 设置）：文件模式拖拽直发手机，剪贴板模式直接读取和发送手机剪贴板；收发双方都显示百分比、进度条与速度。
- 启动：桌面快捷方式「口袋」；应用会自动拉起本地 Node 服务（8570）。旧的 PowerShell 悬浮窗已删除。

## 8. 实测记录（2026-11-08，模拟器 + 本机电脑端）

| 场景 | 结果 |
| --- | --- |
| 电脑端页面出现「局域网互传 / 互传收到的文件」 | 通过 |
| 电脑端 UDP 收到手机广播并列出设备 | 通过（注入 UDP JSON，`/api/transfer/devices` 返回设备） |
| 电脑 → 手机：offer + 上传 2MB 随机文件 | 通过，大小一致 |
| 手机 → 电脑：口袋文件里「发送到设备」 | 通过，落在 `library/transfer/20261108102905-中文文件名.txt`，56 字节 |
| 手机端 HTTP 服务（8572） | 通过，`/api/transfer/info` 返回 `10.0.2.16:8572` |
| 中文文件名 | 通过（Node 客户端直接发 UTF-8；用 Git Bash + curl 发中文会被终端转成 GBK，属测试工具问题） |
| 下载 / Range | 通过（哈希一致） |
| 口袋文件：列表、图片缩略图、预览地址 | 通过（缩略图由 `/__pocket/files/<id>` 提供） |
| 互传：设备列表、最近收到、刷新 | 通过 |

已知限制：

- 手机端服务随 App 进程存活；App 被杀掉后对端会显示离线。
- 接收默认自动保存（局域网可信设备模型）；文件一律进 `files/transfer/inbox`，不会直接进系统相册/下载。
- 同一台电脑同时只能跑一个电脑端服务（8570 / 8571 端口独占）。
